Current deliverables

  1. Basic CLI anomaly detection: analyze a local series and read its findings.
  2. Trend and seasonal analysis: refine the expectation and find sustained changes.
  3. Incomplete-period monitoring: compare finalized data while periods remain open.
  4. Related-metric analysis: inspect declared ratios, gaps, and delayed responses.
  5. Evidence and review policy: judge support and review eligibility.
  6. Python integration: embed validated analysis in an application.
  7. Anomaly detection Skill: get a guided explanation and optional chart.
  8. Read-only MCP server: let an agent inspect local findings and evidence.

Future direction — planned, unimplemented

Each future lane has three ordered stories. Their acceptance criteria and proposed verification scenarios describe intended behavior; implementation and review evidence will be added as the work is delivered.

  1. Historical evaluation: replay cutoffs, measure reviewed-incident timing, and compare settings on held-out history.
  2. Calendar and data readiness: use local calendar periods, check source freshness, and compare related metrics before a period closes.
  3. Business-aware expectations: represent multiple seasonal cycles, account for rate volume, and review possible new baselines.
  4. Continuous analysis: resume state, append finalized samples, and retain an evidence history when data is corrected.
  5. Cohort investigation: separate entity histories, locate additive contributors, and distinguish performance changes from population mix.
  6. Investigation memory: preserve reviewed outcomes, export inspectable evidence bundles, and find comparable reviewed cases.

Each capability has one primary lane; dependencies show shared prerequisites. Future lanes are proposals without release dates or delivery commitments. The caller owns notification delivery and operational actions.

Coverage reflects saved capability reviews. It does not measure detection accuracy on real-world data.
