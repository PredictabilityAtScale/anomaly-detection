# Public forecasting API (0.6.0)

`forecast_series(dataset, settings=None)` is a local, deterministic Python API
with a separate `forecast-v1` JSON contract. It returns a validated
`ForecastResult`; it does not dispatch through or alter `analyze`, distributions,
CLI/MCP tools or Guard recipes. No hosted service or credentials are involved.
This API requires **0.6.0 or later**; published 0.5.0 wheels do not include it.

Version **0.7.0** adds opt-in
[`historical_anomalies`](historical-anomalies.md), versioned separately as
`historical-anomalies-v1`. It returns native signed residual evidence and
first-detection patterns from this same historical analysis. Omitting the option
keeps existing forecast behavior; no second analysis or service is required.

```python
from anomalyzer import ForecastDataset, ForecastSettings, forecast_series

dataset = ForecastDataset(
    id="daily-usage", units="USD", interval="day", timezone="UTC",
    values=[10 + .5 * index for index in range(86)] + [None],
    period_statuses=["complete"] * 86 + ["partial"],
)
result = forecast_series(dataset, ForecastSettings(horizon=30, lower_bound=0))
if result.status == "completed":
    print(result.predicted[0])  # 53.5: future starts AFTER the partial chart bucket
    print(result.model.fit_window)  # (30, 85), inclusive original positions
else:
    print(result.reason)
print(result.model_dump_json(indent=2))
```

Bare ordered numeric lists and dataset dictionaries accept separate settings.
Canonical request dictionaries, `ForecastRequest` objects and JSON strings keep
settings inside `config`; separate settings with those requests return invalid
input. `ForecastDataset`, `ForecastSeasonality`, `ForecastSettings`,
`ForecastRequest`, `ForecastCounts`, `ForecastModel` and `ForecastResult` are public
Pydantic models. Direct model validation raises `ValidationError`; the function
returns a stable unavailable result for invalid input. Unknown fields, numeric
strings, booleans as numeric input, nonfinite measurements and invalid limits
are rejected. A null observation requires an explicit status.

The proposed field names and `forecast-v1` version are retained:

```json
{
  "schema_version": "forecast-v1",
  "task": "forecast",
  "dataset": {
    "id": "daily-usage", "units": "USD",
    "values": [10.0, 11.0, null],
    "period_statuses": ["complete", "complete", "partial"],
    "interval": "day", "timezone": "UTC",
    "timestamps": ["2026-11-01T00:00:00Z", "2026-11-02T00:00:00Z", "2026-11-03T00:00:00Z"]
  },
  "config": {
    "horizon": 30, "trend": "auto", "seasonality": "auto",
    "outlier_handling": "robust", "trend_adjustment_pct": 0,
    "lower_bound": 0, "max_training_points": 56,
    "max_inference_points": 768, "max_points": 6000,
    "max_runtime_seconds": 2.5
  }
}
```

That shape illustration returns `insufficient_history`; it is not a successful
fixture. A complete example can replace values with the 86-point series above.
Pass the JSON text directly to `forecast_series`, or use
`ForecastRequest.model_validate_json(text)`. Schemas are generated by
`python scripts/export_schemas.py` into
[`forecast-request.schema.json`](../schemas/forecast-request.schema.json) and
[`forecast-result.schema.json`](../schemas/forecast-result.schema.json).
Cross-field semantics, finite numbers and calendar cadence are enforced by the
Python models; JSON Schema alone cannot express all of those checks.

## Measurements and calendars

| Status | Measurement | Initial forecast-v1 policy |
| --- | --- | --- |
| complete | Finite signed number, including true zero | Observation available for fitting |
| partial | Finite partial measurement or null | Supported only in a contiguous tail; excluded from all fits, retains position |
| missing | null | Explicit `missing_history`, including a missing tail |

Omitting statuses means all supplied **numeric** values are complete. There is
no implicit fill, interpolation, resampling, gap compression, or conversion of
missing/partial values to zero. Internal partial periods return `missing_history`
as an unsupported gap policy. Fitting requires at least eight complete buckets
and at least one full declared seasonal period within the training window.
Do not mark uncertain source completeness as complete merely to get a result.

Timestamps are optional for already bucketed positional data. With timestamps,
every position, including partial and missing, needs a unique, ordered,
offset-aware ISO 8601 bucket start. An IANA `timezone` is validated even for
positional data. Cadence is contiguous; omitted dates are invalid input rather
than silently filled. Weeks start at local midnight on the caller's initial
weekday. Months start on day one and years on January one. Daily and weekly
cadence follows local dates; months and years advance calendar fields. An hour
advances in UTC, so a fall-back repeated local hour with distinct offsets is
valid, and a spring-forward skipped local hour is valid. No month/year/day is
converted into an equal elapsed-second duration. Calendars with nonexistent
local midnight boundaries are rejected rather than shifted implicitly.

Seasonality is a period in **bucket positions**: `{"period": 7}` means seven
daily buckets, while `{"period": 24}` means 24 hourly buckets. Explicit annual
recurrence can mean 12 monthly buckets or 365 positional daily buckets; the
latter cannot track leap-day alignment and is not a calendar-year model.
Auto detects a single conservative repeating lag (up to 512), with lag-one
fallback and diagnostics. It can miss smooth cycles that resemble lag-one
persistence. Use a known domain period explicitly. Three cycles must fit inside
the inference window; the default 56-bucket training cap cannot discover a
24-hour cycle without increasing it. Multiple simultaneous seasonalities and
calendar effects require a future explicit model.

## Settings and limits

| Field | Default | Meaning |
| --- | --- | --- |
| horizon | 30 | 1–6000 future bucket positions |
| trend | auto | auto, none, linear or exponential; unsupported trend fits can select none |
| seasonality | auto | auto or `{"period": P}`, integer P from 1–1500 |
| baseline | legacy | legacy or recent-level-v1, described below |
| outlier_handling | robust | robust or include, described below |
| trend_adjustment_pct | 0 | -50 through +200; multiply only future learned trend change by 1 + pct/100 |
| lower_bound | null | Optional finite bound for expected/predicted, no implicit nonnegative assumption |
| max_training_points | 56 | 8–6000 trailing complete positions for the current scenario fit |
| max_inference_points | 768 | 8–4096 leading positions within that fit for season discovery |
| max_points | 6000 | Maximum original chart positions, including partial/missing |
| max_runtime_seconds | 2.5 | Positive cooperative request budget, up to 3600 seconds |

The trend primitive can use only the last `max(256, 4*period)` points inside
the requested fit window; `effective_trend_window` reports the actual subset.
Eight points permit a scenario, but trend fitting needs at least
`max(8, 4*period)`; less history selects a seasonal-only fallback. Caps do not
pad insufficient history. The public limits are broader than UsageTap's
interval-specific transport limits; the bridge preserves those limits.

## Fixed scenario decomposition

The scenario uses only the latest bounded complete observations, never partial
measurements, synthetic future values or replacements from historical anomaly
analysis. Select the lag, fit the trend, construct one future seasonal cycle,
and freeze it for the entire horizon. If M is the fit length, P the selected
period, a=M-1 and c[p] the next-cycle reference:

```text
level = mean_p(c[p] - learned_trend.change(a, M+p))
offset[p] = c[p] - level - learned_trend.change(a, M+p)
component[t] = level + factor[t] * learned_trend.change(a, t-fit_start)
seasonal[t] = offset[(t-fit_start-M) modulo P]
prediction[t] = optional_bound(component[t] + seasonal[t])
```

`factor` is one for every supplied historical/partial bucket and
`1 + trend_adjustment_pct/100` only after the final supplied bucket. The anchor
is the final complete observation; a partial tail advances time from that
anchor. Adjustment therefore scales the whole future learned trend change,
including elapsed partial-tail time, for linear and exponential trends. It does
not change the learned rate, historical components, expectations or seasonal
shape. Common future prefixes are exactly equal for different horizons.

`trend[N+H]` is the **unbounded** level/trend component. A negative fitted
component is meaningful even when `lower_bound=0` bounds predicted quantities.
`seasonal_component[N+H]` is signed and has a zero-mean cycle. With bounding,
predicted need not equal the sum of the displayed components. The legacy bridge
clamps the trend copy to satisfy UsageTap's nonnegative chart contract.

In include mode, least squares retains all observations and a seasonal reference
is the previous matching observation, trend-adjusted. In robust mode the trend
primitive uses Huber reweighting and MAD extreme screening, replaces screened
fit references internally, then refits least squares. `downweighted_count`
describes the screening stage, not a final weighted-regression sample count.
Seasonal references use up to four prior matching values, trim the smallest and
largest, and weight retained references modestly toward recency. Before four
cycles, use the previous matching observation. Trimming and downweighting are
different from an extreme screening exclusion; a trimmed reference is not
automatically marked an outlier. Original actuals are never modified.

The returned `outlier_indices` union current-fit screening positions and
historical reference-adjustment positions, all in original chart coordinates.
`model.outlier_policy` separates current screening, historical training and
calibration adjustments, and evaluation replacements. No historical replacement
enters the current forecast fit. Compare robust and include scenarios; robust
does not inherently mean more accurate and can distort sustained changes.

## Historical expectations and maturity

Historical `expected[N]` is separate from the current fitted decomposition.
To prevent future lag selection from rewriting earlier expectations, auto
history freezes selection on the first
`K=min(max_training_points, max_inference_points)` complete observations, using
the existing conservative inference primitive. Its discovery excludes the final
reserved point; both discovery and confirmation windows are reported. Trend is
frozen from the same K-point training prefix. No historical expectation is
published before K: lag selection used information from that prefix. With an
explicit period under the default `legacy` baseline, historical training is
`max(28, period)` and no inference is performed. The opt-in recent-level
training rule is described below. If training is incomplete, history stays null/unavailable while a
current scenario may already be available.

Subsequent expectations use earlier seasonal references and the frozen trend.
The next 14 observations are residual calibration; earlier residuals can support
`reference_only` or `provisional` comparisons. Only subsequent `calibrated`
positions set `eligible=true`. Default auto settings first permit expected at
index 56 and calibrated eligibility at index 70. The expectation at a target
never uses that target's observed value. Changing a suffix or appending values
cannot change earlier expectations, eligibility or maturity with the same
dataset origin and settings. Removing or changing a leading prefix is a new
history origin and does not carry that guarantee.

Historical robust mode retains the existing analyzer's frozen training,
calibration screening and extreme-reference replacement rules. This may cause
historical expectations to follow regime changes poorly. Historical readiness
reports baseline/calibration diagnostic caution separately from
`forecast_applicability="scenario_available"`. Neither calibrated maturity,
readiness, nor no anomalies establishes health, forecast accuracy or confidence.
Calibration diagnostics and excluded-reference metadata can be finalized after
the calibration tail; their invariance is not the historical expectation promise.
The existing standalone `analyze` inference behavior is unchanged.

## Results and failures

A completed result includes schema/task and engine version, SHA-256 fingerprint
of the validated request with defaults/statuses resolved, resolved settings,
complete/partial/missing counts, all required series, original outlier indices,
maturity per position, origin index, optional future timestamps, model windows,
selected parameters, inference diagnostics, readiness, policy effects and
limitations. Fingerprints identify requests; they are not anonymization and must
be handled with the source data's privacy level. Schema validation alone does
not validate scientific applicability.

Unavailable series and model are **null**, never empty fabricated forecasts.
Validated requests retain fingerprint/config/counts even on failure; malformed
requests cannot provide them and return null. Stable reasons are
`unsupported_contract`, `invalid_input`, `insufficient_history`,
`missing_history`, `analysis_incomplete`, `budget_exceeded`, `nonfinite_result`
and `analysis_failed`. Numerical failures may also be caught by the underlying
analyzer and reported as `analysis_incomplete`. Runtime budgets span validation,
selection, fitting, evidence and projection through cooperative checks. They
do not kill a running process; the caller must retain a hard invocation timeout.
No incomplete evidence or partial projection is promoted to completed.

## Held-out evaluation and source coverage

Reproduce the committed anonymous evaluation:

```text
python examples/forecasting/evaluate.py --output docs/forecast-evaluation.json
python -m pytest -q tests/test_forecast.py tests/test_forecast_evaluation.py
```

[`fixtures.py`](../examples/forecasting/fixtures.py) defines 19 deterministic
synthetic series; [`forecast-evaluation.json`](forecast-evaluation.json) records
76 case/baseline/policy runs with three chronological origins each, selected trends/lags,
windows, one-step MAE, multi-step MAE, WAPE and last-observation/seasonal-naive baseline errors. Every
fit ends before its holdout. WAPE is null when the actual denominator is zero.
Overlapping folds are not independent trials. Exact simple trends and declared
cycles are expected favorable cases. Sustained shifts and changing slopes expose
substantial weaknesses: for example, shift MAE is approximately 11.33 (include)
and 10.36 (robust), versus 2.38 for last-observation persistence on that synthetic
fixture. Do not interpret exact synthetic fits as production accuracy.

Private inputs, metadata, replay scripts and detailed results remain local in
ignored `.tmp/`; they are not evaluation fixtures or release artifacts. No future
actual outcomes are available for a supplied forward scenario. The optional
`--private-evidence` mode accepts the older JSON evidence-export shape and refuses
output outside `.tmp/`. It does not parse arbitrary customer CSV exports.
Keep UsageTap's Current method as the comparison default until representative,
reconciled history and reviewed outcomes support a change. See the
[migration checklist](usagetap-forecast-migration.md).

## Smoothed recent level (opt-in since 0.8.0)

```python
result = forecast_series(values, {
    "baseline": "recent-level-v1", "horizon": 7,
    "outlier_handling": "include", "historical_anomalies": {},
})
print(result.model.level_baseline)
print(result.model.historical_level_baseline)
```

`baseline` defaults to `legacy`. Installing 0.8.0 alone changes neither forecast
numerics nor standalone `analyze`, adaptive recipes, distribution detectors or
Guard settings. The explicit versioned option changes eligible historical
expectations as well as forecasts. Contract names stay `forecast-v1` and
`historical-anomalies-v1`; consumers must negotiate the exact engine version and
new config before sending it. Older versions reject the new setting.

Selection runs only if the selected trend is `none`, the season length is one,
and the requested trend is `auto` or `none`. Explicit seasonal periods greater
than one and explicit linear/exponential requests keep their existing models.
No weekly cycle or trend is imposed. This does not fix a missed cycle or prove
that no cycle exists. The diagnostic says no stable cycle or trend was selected;
it describes model selection, not the underlying process.

Include persistence uses the last measured value. SES initializes its level at
the first observation of the preceding at most 56 observations, then updates
`level = alpha * observation + (1-alpha) * level`. Its future scenario repeats
that smoothed level at every horizon, including through partial tails. Every
historical target uses only preceding observations and the same bounded-window
initialization. The window slides; this is a recent-level SES baseline, not an
unbounded-state ETS fit or a forecast interval model.

Outlier handling remains independent. Include feeds every measured observation
to smoothing, without exclusions or labels. Robust feeds the existing causal
four-reference trimmed/recency-weighted level policy to smoothing (before four
observations it uses the last reference); this is smoothing of robust references,
not ordinary SES of all raw values. Existing robust training/calibration screening
and model-only future-reference replacement still apply in historical analysis.
Selection scores predictions against the original held-out measurements under
both policies. Smoothing itself never creates `outlier_indices` or incidents.
`kind=persistence` in robust mode means the retained robust reference policy,
not a claim that the result equals the last raw observation.

The deterministic selector uses the last at most 56 complete fit observations.
It tries alpha values 0.1, 0.25, 0.5 and 0.75 against persistence. It takes up to
six disjoint seven-target chronological folds ending at the selection endpoint,
with at least eight earlier fit observations per fold and at least three folds
(minimum 29 observations). A fold uses its training prefix only, then repeats
its frozen level over all seven holdouts. All candidates see the same folds.
Selection requires seven-step aggregate MAE to improve by more than 5%, wins on
at least two thirds of folds, and aggregate one-step MAE no more than 5% worse.
A numerical tolerance of `1e-12 * max(1, persistence_MAE)` protects ties.
Unsupported, short-history or tied results retain persistence. Among supported
candidates minimum MAE wins; exact candidate ties choose the smaller alpha.
These conservative thresholds are engineering gates, not significance tests.
Folds within selection are not independent evidence of production accuracy.

The objective is always seven **buckets**, regardless of requested output
horizon or interval; a daily bucket gives a seven-day objective. This preserves
forecast horizon-prefix invariance. Longer horizons and other cadences may need
a separately versioned objective after evaluation. Alpha, kind, status, reason,
window, fold windows in original coordinates, candidate losses and gates are
returned in `model.level_baseline`. `not_applicable` explains other model choices.
At most 5 candidates x 6 folds x 56 updates are needed for each selection; each
historical prediction reads at most 56 references. Existing point/runtime limits
and cooperative budget failure semantics apply, including atomic unavailable
results. This adds no numerical dependencies.

Historical selection freezes on the original historical training prefix, before
any exposed target or calibration observation. Auto season selection uses its
existing fixed prefix `min(max_training_points, max_inference_points)`. For an
explicit period of one with eligible recent-level selection, the historical
training prefix is now 56 observations (legacy uses 28). Other explicit model
training boundaries stay unchanged. If a configured prefix is shorter than 29,
persistence is frozen; later data do not mature that model selection retroactively.
Earlier targets remain unavailable. The next 14 residuals calibrate the selected
baseline; only subsequent targets can be calibrated/triggering. Readiness uses
those matching residuals, not legacy residuals or current-fit reconstruction.
Provisional point rows remain point-time evidence; robust calibration rebuilding
is a later reference operation with its own cutoff, as before.

`model.historical_level_baseline` and native
`resolved_settings.forecast_baseline` / `resolved_settings.level_baseline` record
this frozen selection. It participates in origin/calibration fingerprints.
Current and historical selections can differ: both have their own data cutoffs.
Today's selected model is never applied retrospectively. Appending or changing
a suffix with the same origin/settings cannot change earlier Expected, point
scores, maturity or first-detection patterns. Changing the input's leading origin,
settings or engine version creates new provenance; retain old findings unchanged.
Signed native expectations versus lower-bounded display expectations, original
indices, missing rejection and partial-tail availability retain their contracts.

The nested outer evaluation records all 19 fixtures under both baseline choices
and both outlier policies, including three stationary random seeds, isolated
endpoint spikes, a recent real step and a random walk. The new option helps some
stationary and spike cases, slightly worsens one stationary seed, and substantially
lags the noisy real step. Persistence remains selected for the declared random
walk. Trend/seasonal reference fixtures retain their forward outputs. Full scores,
including regressions, are committed; no seed or origin was removed for appearance.
A held-out win on synthetic data is not a promise of accuracy, a calibrated
uncertainty statement, or evidence of health when anomalies are absent.

Method references: [simple exponential smoothing](https://otexts.com/fpp3/exponential-smoothing.html)
and [rolling-origin time-series validation](https://otexts.com/fpp3/tscv.html).
